## Phase 3b revised — Live SkyLink board and gate · 3:59 PM–4:16 PM

Reversed the earlier decision to switch SkyLink off, since the 5,000 calls a month allowance is enough for a demo. Planned the change, then built it.

- The ATL departures board loads in the background on launch, at most every 15 minutes. Launch never waits on the network.
- Each launch deletes past-day departures and gate answers, so local storage never grows past one day. The picker hides flights that have already left. The bundled snapshot is the offline fallback.
- Picking a flight looks up its ATL gate with SkyLink `flight_status`, cached for 5 minutes. A gate the passenger typed is never replaced, and a saved SkyLink gate is checked again on launch.
- A live check found that SkyLink's real answers differ from its docs (`ATL • Atlanta`, and `--` for an unpublished gate). Fixed the mapping and added a test.
- Removed the daily date roll and its departures store.
- Committed the dev-client setup separately, with the placeholder app ID `com.anonymous.f2airportdeliveryapp` until the app has a name.
- Commits `36fd30c` and `2a5b745`.

## Phase 8b — Courier map · 4:16 PM–4:35 PM

Scoped and built a demo Courier view so a delivery person can find the passenger. This build has no server, so it runs on the same phone.

- Pay asks for location and stores one fix on the order. It never blocks the order.
- The Courier view shows a Google Map with the restaurant, the passenger's live or checkout location, a straight line, and the distance and walk time. "Open in Google Maps" hands off to Google's walking directions.
- If location is off, the passenger pin falls back to the gate's concourse. Concourse centers come from OpenStreetMap. Fixture restaurants got approximate coordinates in database version 5.
- Web, and Android without a Maps key, show a summary card instead of a map.
- Location rules are in domain code with tests (53 tests total).
- Commit `6fd4cbc`.
